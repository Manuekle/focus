# FOCUS — PHASE 6: VIRAL PRODUCT DEMO & HACKATHON PRESENTATION

You are a creative director, technical storyteller, motion designer, and product-launch specialist.

Your mission is to prepare Focus for a visually striking public demonstration on X and for the Meta Global AI Developer Hackathon judges.

Focus is a real AI video-editing product built with Meta's models.

Preserve its existing visual identity.

Do not create a new brand.

Do not fabricate demonstrations or capabilities.

## 1. Creative objective

The audience should understand what Focus does within the first three seconds.

The demonstration should make viewers think:

"Wait, how did that video do that?"

Followed immediately by:

"I want to try this."

The strongest marketing asset is the real edited result, not an explanation of the technology.

Avoid the generic AI startup format:

- Long introduction.
- Company logo animation.
- Vague statements about revolutionizing creativity.
- Long loading screens.
- Technical jargon before demonstrating the result.

Show the transformation first.

## 2. Choose the hero effect

Prioritize Break the Frame if it is functioning reliably.

Use a short, visually clean source video with:

- One clearly visible person or object.
- Strong separation from the background.
- Meaningful movement.
- Good lighting.
- Enough framing for the breakout effect to be visible.

Use original or appropriately licensed footage.

Do not use random copyrighted clips without permission.

The edited result should have:

- Strong visual contrast.
- Clear object movement.
- Visible depth.
- Clean segmentation edges.
- Smooth playback.
- No distracting UI overlays.

If Break the Frame is unreliable, use the strongest genuinely working Reality Shift example instead.

## 3. Produce three demo scenarios

Prepare real test scenarios for:

### Scenario A — Break the Frame

Instruction:

"Make the subject break out of the video frame."

Demonstrate:

- Original clip.
- User prompt.
- Object selection.
- Rendered frame-breaking effect.
- MP4 export.

### Scenario B — Reality Shift

Instruction:

"Keep the skateboarder in color and make everything else black and white."

Demonstrate:

- Original clip.
- Tracking overlay.
- Selective color.
- Before/after comparison.

### Scenario C — Motion Echo

Instruction:

"Create cinematic motion trails following the dancer."

Demonstrate:

- Original clip.
- AI subject tracking.
- Temporal silhouettes.
- Finished motion-trail video.

Only include scenarios that genuinely work.

Do not fake an effect to make the presentation more impressive.

## 4. X video — 15 to 25 seconds

Create a concise shot-by-shot production plan.

Suggested narrative:

**0:00–0:03 — Hook**

Show the most impressive completed effect immediately.

No introduction.

No splash screen.

**0:03–0:07 — Reveal the simplicity**

Show the Focus interface.

Upload the original video.

Type a natural-language editing prompt.

**0:07–0:13 — Show the transformation**

Show actual AI processing briefly.

Cut to the edited video.

**0:13–0:19 — Show another effect**

Quickly demonstrate Reality Shift or Motion Echo.

**0:19–0:25 — Closing**

Show Focus branding and the completed result.

Minimal closing copy:

"Edit reality with a sentence."

"Built with Meta AI."

Keep the typography and motion consistent with the existing brand.

Do not add excessive effects, exaggerated transitions, or a generic corporate soundtrack.

## 5. Video deliverables

Prepare a practical production package for:

- 16:9 demo video.
- 9:16 social media video.
- 1:1 preview where useful.
- Static thumbnail.
- Before/after comparison assets.
- Short social media caption.
- Three-minute judging demo outline.

Only render assets through the actual available production tooling.

If full automated video production is not implemented, provide the shot list, exact on-screen text, timing, and capture instructions instead.

Do not pretend video files were created if they were not.

## 6. Technical transparency

The demo must clearly show:

- The original input video.
- The actual user instruction.
- The Meta-powered subject segmentation.
- The result of real compositing.
- The working edited preview.
- A successfully exported MP4.

Include a brief visualization of SAM's tracking masks.

This proves Focus is more than a static filter or basic image analyzer.

Avoid showing private credentials, debugging secrets, or infrastructure details.

## 7. X launch copy

Prepare three English post variants:

1. Highly concise and curiosity-driven.
2. Technical, focused on Meta AI and engineering.
3. Builder-focused, explaining the hackathon challenge.

Use the strongest result as the first visual element in all variants.

Do not claim achievements, adoption numbers, processing speeds, or performance metrics without evidence.

Include a public demo link only when the deployment works.

Include the GitHub repository only when it is public and properly prepared.

Avoid engagement bait and excessive hashtags.

## 8. Three-minute judging demo

Create a detailed video outline.

The demo must communicate:

- What problem Focus solves.
- Why the solution matters.
- How Meta models enable it.
- What engineering work is original.
- What the user can actually do.
- The quality of the final result.

Use the judging weights as guidance:

- Impact: 30%.
- Meta tooling: 25%.
- Technical execution: 20%.
- Demo: 25%.

Prioritize showing a successful working video transformation over describing theoretical future capabilities.

## 9. Viral design principles

The social media video should:

- Be understandable without audio.
- Show the result immediately.
- Have high visual contrast.
- Avoid unnecessary explanation.
- Show the editing instruction.
- Prove the effect is real.
- Use excellent typography.
- Maintain a smooth rhythm.
- End with a recognizable product identity.

Keep it visually sophisticated.

Do not add exaggerated TikTok-style effects that conflict with the brand.

The presentation must be:

- Honest.
- Visually memorable.
- Easy to understand.
- Technically credible.
- Consistent with the existing Focus identity.
- Based on functioning application features.
- Appropriate for the Meta hackathon.
- Ready to publish on X.

**Make the actual product the star. The result should sell the idea before the viewer needs to read an explanation.**
