# Rotoscope

Rotoscope redraws a live-action clip, frame by frame, as one of your characters. It is behind `NEXT_PUBLIC_ENABLE_ROTOSCOPE=true` (build-time flag) and lives at `/rotoscope`.

Muse Spark reads and reviews frames and Muse Image draws them. Higgsfield is an optional second drawer (`HF_CREDENTIALS`).

## How a run works

1. **Create.** Upload a clip (or pick a segment), choose a character sheet and set frames per second and length. Focus extracts the frames and auto-crops to the performer.
2. **Prepare.** DWPose runs on every source frame and on the character sheet, and Muse Spark describes the character. These steps run in parallel. Pose guides are then rescaled to the character's proportions.
3. **Draw, in order.** For each open frame Muse Spark reads the source frame (one frame ahead), the drawer produces the character in that pose, the result is keyed to alpha, and DWPose measures the drawing. Each frame receives the previously approved one for continuity.
4. **Check.** Measured checks cover pose match, colour, proportions, registration, scale and stature. A frame that passes them goes to a Muse Spark review. A failed check sends feedback and lessons into the next attempt.
5. **Report.** The run produces a GIF, a transparent MOV and a score table. Compare exports put the reference and the drawing side by side.

A frame is **never marked approved** unless every measured check passes. Redrawing a frame is one attempt, not a retry loop, so cost stays predictable.

## Where things live

| Path | Role |
| --- | --- |
| `app/rotoscope/` | Studio UI: canvas, player, activity log, prompt lab, mapping inspector |
| `app/api/rotoscope/` | Thin route handlers |
| `server/rotoscope/pipeline.ts` | Frame loop and read-ahead |
| `server/rotoscope/draw.ts` | Drawer calls and prompt assembly |
| `server/rotoscope/measures.ts`, `fidelity.ts`, `guardrails.ts` | Measured checks and the approval gate |
| `server/rotoscope/body-map.ts`, `joints.ts`, `mannequin.ts` | Pose geometry and character proportions |
| `server/rotoscope/higgsfield.ts` | Optional second drawer and reference upload cache |
| `server/rotoscope/cli.ts` | Terminal entry point (`pnpm rotoscope`) |
| `services/animation-worker/` | Python DWPose (rtmlib / ONNX) |

Run data is stored under `FOCUS_DATA_DIR/rotoscope/{run}/` (`manifest.json`, `source/`, `work/`, `report/`).

## Requirements

- The Python DWPose environment in `services/animation-worker/.venv` (see its README).
- FFmpeg and FFprobe on `PATH`.
- `MODEL_API_KEY` for the Meta Model API.

## Command line

```bash
pnpm rotoscope init --video clip.mov --character hero.png --fps 9 --seconds 1 --run test-1s
pnpm rotoscope generate --run test-1s --limit 3 --dual   # resumes where it stopped
```

## Tests and fixtures

Unit tests never call a model. The `server/rotoscope/__fixtures__/wave/` character sheets are synthetic flat-colour shapes generated by `scripts/make-wave-fixtures.mjs`, so the repository carries no third-party artwork. Run `node scripts/make-wave-fixtures.mjs` to regenerate them.

## Rights

Every Rotoscope run requires the content-rights acknowledgement described in the main [README](../README.md#content-rights-confirmation). Only use footage and characters you are allowed to use.
