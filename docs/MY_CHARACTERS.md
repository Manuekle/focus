# My characters

`/characters`, enabled by `NEXT_PUBLIC_ENABLE_FLIPBOOK=true`, uses the existing Focus account. Its entry point is also available in Flipbook's sidebar and empty state.

Start with **Shion** (`public/characters/shion.png`) or **Tomohito** (`public/characters/tomohito.png`), or upload a PNG, JPEG or WebP reference. Creating a character saves the original; it does not call a model. **Create design** generates one full-body image. **Generate change** edits the selected version. Every generation includes the immutable original for face, hair, eyes and ears; the selected version determines the current outfit. **Take from a photo** holds one outfit photo and one style picture (PNG, JPEG or WebP, same size limit as other uploads, stored beside the character; a new one replaces the old). While attached, every generation is told to dress the character in the outfit photo's clothing (only the clothing: never its person, face, body or pose, even from a real photo) and/or to redraw it in the style picture's line work, colouring and shading; the original then no longer imposes its own outfit or style. With an empty change box, the attached photos are the change. Removing a photo stops it; versions already drawn keep their look. Elf-chan, Denji, Reze, Ichika and Seita are retired as templates; previously saved characters remain accessible.

Each successful image becomes an immutable version. Names and the selected version can change. Selecting, comparing, renaming and downloading do not call AI. Failed or interrupted work keeps the last valid version and the attempted instruction. Generation requests use operation IDs, so a duplicate submission does not pay twice. Work is counted in the global active-work cap. `FOCUS_CHARACTER_IMAGE_BUDGET` defaults to 16 attempts per character; clearly unbilled refusals are returned to the allowance, while uncertain timeout outcomes remain counted. Up to 32 versions are supported.

`server/characters/` owns validated state and images under `<FOCUS_DATA_DIR>/characters/`. This data does not expire with temporary Flipbook uploads. Writes are atomic; jobs and locks share process-wide state, following the single-container architecture of the rest of Focus. An interrupted process reports the interrupted generation instead of showing an endless spinner. A queued request whose response was lost can be replayed with the same operation ID.

**Use in Flipbook** opens the exact selected version with no generation or temporary re-upload. Only **Create animation** begins the existing analysis and pose pipeline. The new animation copies both the selected design and the original identity image. Its saved `characterSource` records character, version and their names; later character edits or renames do not modify that snapshot. The original identity portrait is included in every pose generation and reference preparation, separately from the selected outfit. A link returns from the animation to its character.

**Animate together** (`/flipbook?together=1`) draws two to four saved characters in one scene, for 1–6 seconds, at 8 drawings per second: a fight, a dance, a chase. Each character is drawn from its selected version, copied into the animation, and only its owner can open it. See [Scenes](FLIPBOOK.md#scenes-several-characters-together).

Characters, references and generated images require their owner's session. Character-derived Flipbook data, actions and media also enforce ownership. The older anonymous upload workflow retains its existing UUID capability URLs. The video editor's existing account and media model is unchanged.

The studio follows Rotoscope's workspace: the selected design fills the canvas (with **Compare**), the versions run underneath, and a resizable, hideable inspector on the right has three tabs: **Design** (the change, suggestions, the outfit/style photos and Generate, which stays in reach), **Version** (name, when and from what it was drawn, what was asked, download, delete) and **Animation** (height, weight and animation data). Narrow screens stack picture, versions and inspector. The studio uses existing Focus components and typography. The illustration remains visible during generation; a status message describes actual work instead of a fabricated percentage. Mobile omits the desktop library sidebar. Comparison shows two contained images with a shared stage. Fields have visible labels, version buttons expose their selected state, and controls have visible keyboard focus.

The feature uses Muse Image for initial generation and editing; Muse Spark and SAM remain part of Flipbook's existing animation pipeline. It adds no model provider, database, browser agent or automatic source search.

## Animation data

Each version keeps the data its sheet alone decides for Rotoscope: the DWPose pose of the sheet, Muse Spark's identity description, the pose sheet (one Muse Image drawing), the named palette, the body measured on the grid and Muse Spark's art style sheet (line work, eyes, shading, hair, folds, colour, finish) (`server/characters/kit.ts`, stored as `kits/<version>/` beside the character).

Muse Spark writes each Rotoscope frame's Muse Image prompt (`writeFramePrompt`; `--writer template` draws from the template instead). It sees the images Muse Image will get and the template prompt as its model, keeps the template's facts, writes the target pose itself, and is shown the kit's prompt memory: the target pose parts of earlier prompts whose drawings were approved, and of those whose drawings failed with what was wrong (`server/rotoscope/prompt-memory.ts`, `kits/<version>/prompt-memory/<run>.json`, saved when a run made from the kit stops). The character's real height and weight live on the character and are said in the description and the pose sheet.

The data is prepared on its own right after a version is drawn; **Animation data** in the editor shows it, and prepares it again after a height or weight change. A Rotoscope run of a saved version finds it by the sheet's pixels and copies it in instead of making it again. When the version has none yet, the run's own analysis is saved as its data, never over data My characters already holds; a character without a height and weight then takes the run's. A run made with a different height or weight reuses the pose, palette and build and redraws the description and pose sheet for itself.

## Camera views

The character generator preserves the reference's camera unless a change is requested. Shion and Tomohito keep their original front-facing pose. Flipbook offers **Keep original view**, **Front**, **Three-quarter**, **Side profile**, **Back**, **From above** and **From below**. Screen movement is independent of the camera; choosing rightward travel does not turn a frontal character into a profile. The view is persisted in the animation plan and used for reference preparation, every drawing, repairs, background perspective and review. Complete frontal references can be used directly.

The internal anatomy guides match the selected view. A view without matching guides, such as the back, uses the textual phase mechanics; it never substitutes a profile mannequin. Frontal and rear strides do not use the side-view stride estimator. Idle loops preserve the reference's resting posture when no catalog posture is selected. Wave prompts keep the same arm throughout the sequence.

These are fixed-camera animation cycles. They do not add a 3D rig or a continuous camera orbit. The model still needs visual review, especially for hands, asymmetric details and newly inferred views.

## Verification

Offline tests in `server/characters/` use the user-created illustrations of Shion and Tomohito with replaced paid services. They cover template creation, retirement of the old starter, ownership, original-reference continuity, immutable versions, comparison/selection without generation, failed and interrupted jobs, budgets, duplicate requests, supporting-reference limits, HTTP origin checks, private media and the independent Flipbook copy. `server/animation/access.test.ts` checks private derived animations and compatibility with anonymous uploads.

The historical manual live test from 2026-10-27 used Elf-chan for the initial design, a green-coat edit, a front-facing version and Wave animations. Details and remaining visual limits are recorded in [the delivery report](MY_CHARACTERS_VALIDATION_2026-10-27.md).
